# Threads Monitor

> **摘要**：Threads Monitor 記錄任何一篇公開 Threads 貼文的公開數字（觀看、讚、留言、轉發、引用、分享）、
> 發布時間與貼文內文，在發文後 72 小時內依排程定時抓取，並保留 72 小時最終數字。它讀取的是未登入就看得到的
> 公開貼文頁，不登入、不用 cookie、不用任何 API 權杖。有兩個版本：下載就能用的**資料夾版**（`standalone/`，
> 結果寫成 CSV），以及自架的**網頁版**（PHP 8.3／Laravel 12，預設 SQLite，多帳號）。預設以 Googlebot 的
> User-Agent 抓取，可能違反 Meta 的服務條款；使用前請先讀[風險與免責聲明](#風險與免責聲明)。
> 本專案與 Meta 無關。MIT 授權。

## 這是什麼

給一條 Threads 貼文網址，系統就會：

- 記錄這篇貼文的**發布時間**（顯示到日期與小時）與**貼文內文**
- 在**發文後 72 小時內**定時記錄觀看、讚、留言、轉發、引用、分享的數字
- 在 72 小時整記下 **72 小時最終數字**，列出每一筆快照和它比上一筆增加多少，並畫出觀看數隨時間變化的曲線

任何人的公開貼文都可以追蹤，不需要是你自己的帳號，也不需要任何 Threads／Meta 帳號或 API 權杖。

## 功能

- 貼上網址就開始追蹤；支援 `threads.com`、`threads.net`、`/t/` 短網址，以及 App「分享」產生的 `/share/…` 分享連結（自動還原成原始貼文）
- 發布時間取自頁面；還沒抓到頁面前，先用貼文代碼推算（標示「推算」）
- 依發文後經過的時間自動調整抓取頻率，72 小時整抓最後一次
- 分時紀錄：每次抓取都列出來，並附上和前一筆相比的增量；前後兩筆相隔至少半小時時，另外換算成每小時增量
- 第一次抓取成功時存下貼文內文，顯示在清單與貼文頁
- 自己的**分組**：清單依分組分區顯示，每個分組是可以點開的區塊，沒有分組的貼文放在最後的「未分類」。分組區塊預設收合；有篩選時會自動展開有符合結果的區塊，沒有篩選時瀏覽器會記住你展開了哪些區塊。在清單頁就能新增、改名、刪除分組與調整順序
- 新增貼文只需要貼網址；分組、**標籤**、**備註**都是之後再設定，直接在清單上的貼文卡片或貼文頁頂端編輯。你的分組、標籤、備註其他帳號都看不到
- 貼文還沒抓取成功之前，帳號名稱取自你加入的網址，並標示「**未驗證**」；「開啟貼文」連結一律使用標準網址 `https://www.threads.com/t/<代碼>`
- 可依關鍵字、狀態、標籤、分組搜尋與篩選；關鍵字也會比對你自己的分組名稱，而且不分大小寫，英文以外的字母也一樣。篩選結果有自己的網址，可以加入書籤
- 拿不到的數字顯示「**無法取得**」（英文介面是 Not available），作者隱藏的讚與觀看顯示「**作者隱藏數字**」（英文介面是 Hidden by author），**絕不用 0 代替**
- 失敗看得見：被擋、頁面格式改變、貼文刪除都會標示原因與連續失敗次數；已刪除或失敗的貼文仍會顯示停止前最後抓到的數字
- 多帳號：不開放註冊，由管理員建立帳號；每個人的清單各自獨立
- 介面支援繁體中文與英文，自動依瀏覽器語言切換；也可以用頁首的切換鈕手動切換。按鈕上寫的是要切換過去的語言：中文介面顯示 **EN**，英文介面顯示 **中文**
- 亮色與暗色主題：在你用頁首的切換鈕選定之前，跟隨系統設定
- 預設使用 SQLite，不需要另外架資料庫；也可以改用 MySQL 8

## 運作原理（摘要）

用 Googlebot 的 User-Agent 對貼文公開網址發一次普通的 HTTP GET，伺服器回傳的 HTML 裡內嵌了這篇貼文的 JSON 資料（讚、留言、轉發、引用、分享、發布時間、貼文內文），觀看數則在頁面另一段設定裡。排程以發布時間為起點：預設 72 小時內每小時抓一次，72 小時整寫入最終數字。想少抓幾次（降低被擋的機率），可以設定 `THREADS_POLL_BANDS`（資料夾版是 `settings.ini` 的 `poll_bands`），例如改回 24 小時後每 3 小時一次。

## 快速開始

需要 PHP 8.3 以上（含 `bcmath`、`curl`、`mbstring`、`xml`、`pdo_sqlite` 擴充）與 Composer。只想在自己電腦上試用：

```bash
git clone <repo-url> threads-monitor
cd threads-monitor
composer install --no-dev
php artisan threads:install
php artisan serve
```

`threads:install` 會先檢查 PHP 擴充，再建立設定檔與資料庫、詢問管理員帳號，最後印出步驟總結（任何一步失敗就以非 0 的結束碼結束）。接著打開 <http://127.0.0.1:8000>，用剛建立的管理員帳號登入。

如果 `composer install` 在這之前就停下來，顯示 `requires PHP extension ext-bcmath … but it is missing from your system`（或 `ext-curl`、`ext-xml`），請照[需求](docs/SELF-HOSTING.zh-TW.md#0-需求)安裝缺少的擴充後再執行一次；不要執行 `composer update`，也不要用 `--ignore-platform-req`（詳見[疑難排解](docs/SELF-HOSTING.zh-TW.md#composer-install-說缺少-php-擴充)）。

在伺服器上，安裝程式還會印出一行 cron 設定。這一行要放進 **web 使用者**的 crontab（`sudo crontab -u www-data -e`），而且要在**設好檔案權限之後**才放，否則排程會失敗。請照伺服器教學的順序做。

## 帳號與資料範圍

- **不開放註冊**。第一個管理員在安裝時建立（或用 `php artisan threads:create-admin <email>`）；其他帳號由管理員在 `/users` 建立、編輯、重設密碼、停用或刪除。
- 每個人可以在 `/account/password` 改自己的密碼。改密碼後，你在其他裝置上的登入會被登出；管理員重設你的密碼或停用你的帳號時，你在所有裝置上都會被登出。
- 登入有次數限制：同一個 email 每 10 分鐘 10 次，同一個 IP 每分鐘 5 次（IPv6 以 /64 網段計算）。登入失敗的回應時間和這個 email 有沒有帳號無關。
- **清單各自獨立，抓取資料共用**：同一篇貼文不論幾個人追蹤，系統只抓一次，大家看到同一份數字。後來才加入的人，也看得到他加入之前抓到的快照。
- 分組、標籤與備註屬於每個人自己的清單。
- 加入或移除貼文時顯示的訊息，不論是否有其他人在追蹤都一樣。
- 「從我的清單移除」只影響自己；最後一個人移除時才會停止追蹤並刪除資料。
- 管理員也看不到別人的清單。
- 系統存的是乾淨的貼文網址、公開數字與貼文內文；分享連結裡的分享代碼與追蹤參數不會存下來。

## 風險與免責聲明

- **預設的 User-Agent 冒用 Googlebot。** 抓取之所以拿得到數字，是因為預設的 `THREADS_USER_AGENT` 是 Google 爬蟲的字串，而發出請求的並不是 Google 的主機。這種使用方式**可能違反 Meta 的服務條款**，你的 IP 也可能因此被限制或封鎖。可以在 `.env` 用 `THREADS_USER_AGENT` 改掉，但換成其他 User-Agent 後頁面就不再含有數字（見[運作原理 §3](docs/HOW-IT-WORKS.zh-TW.md#3-抓取方式user-agent-決定拿到什麼)）。
- **與 Meta 無關**：本專案與 Meta Platforms, Inc. 及 Threads 沒有任何關係，也未獲其認可或贊助。「Threads」是其各自所有者的商標。
- **會保存他人的內容**：系統會存下每一篇追蹤中的貼文的內文，這可能是別人的貼文。請比照你蒐集的其他個人資料謹慎處理。
- **共用資料對新加入的人可見**：因為抓取資料是共用的，之後才加入同一篇貼文的人，看得到全部快照，包括他加入之前抓到的。
- **觀看數是網頁顯示的值**：有幾分鐘延遲，不保證等於作者在 App 或官方 API 看到的數字；這也是最可能被改版拿掉的欄位。
- **可能隨時失效**：抓取依賴 Threads 網頁的內部格式與 Googlebot User-Agent。Meta 改版或開始驗證爬蟲來源時，抓取會全部失敗（顯示 `parse_failed` 或 `blocked`），需要等程式更新。
- **限流門檻未知**：只做過小量測試。追蹤量大時請先觀察被擋的比例，不要把抓取間隔調得更密。
- 「貼文已刪除」的判斷有一部分是推測。只能追蹤公開貼文；私人帳號、已刪除的貼文拿不到數字。
