# ThreadsMonitor（資料夾版）

ThreadsMonitor 會在 Threads 公開貼文發布後的 72 小時內持續追蹤，把瀏覽、讚、回覆、轉發、引用、分享的數字寫進 CSV 檔，用 Excel、Numbers 或 Google 試算表都能直接打開。

它就是一個程式加一個資料夾。不需要伺服器、不需要資料庫、也不用註冊帳號。你把貼文網址貼進一個叫 `urls.txt` 的文字檔，程式就把數字寫進同一個資料夾。可以讓電腦自動更新，也可以隨時手動更新。

## 它會做什麼

- 你在 `urls.txt` 列出想追蹤的貼文，一行一個網址。可以分組（例如一個客戶一組），也可以加上標籤和備註。
- 每篇貼文有自己的資料夾。程式每檢查一次，就在那篇貼文的 `snapshots.csv` 加一行（一筆**快照**），附上日期和小時。
- 檢查頻率：發文後 72 小時內每小時一次；72 小時整再檢查最後一次，這一次就是 **72 小時最終數字**。想少檢查幾次（降低被擋的機率），可以設定 `settings.ini` 的 `poll_bands`。
- 主資料夾裡的 `index.csv` 把每篇貼文列成一行：最新數字、72 小時最終數字、狀態、標籤、備註、貼文內文開頭，以及它的資料夾在哪裡。
- 兩種更新方式：**自動排程**（電腦每 10 分鐘在背景執行一次程式）和**手動更新**（雙擊程式，立刻檢查所有貼文）。

## 開始之前

請先看過這些限制：

- **電腦要開著。** 自動排程只有在電腦開機、沒有睡眠時才會執行。如果 72 小時那一刻電腦是關的，程式會在電腦回來後立刻補抓最後一次，寫下實際時間，並標記 `late_final = true`。它絕不會把延後的數字假裝成 72 小時整抓到的。
- **只限公開貼文。** 程式讀的是任何人不登入就能打開的公開頁面。私人、已刪除或有年齡限制的貼文讀不到。
- **Threads 隨時可能改版。** 這個工具讀的是公開網頁，不是官方 API。如果 Threads 改了頁面或開始擋這類請求，工具會停止運作，直到更新為止。
- **瀏覽數**是公開網頁上顯示的數字，可能和作者在自己的洞察報告裡看到的不同。
- 作者隱藏按讚數和瀏覽數時，那些欄位會留空。空白儲存格一律代表「拿不到」，絕不代表零。

## 風險

- **它會冒用 Google 爬蟲的身分。** 程式預設告訴 Threads 自己是 Googlebot（Google 的搜尋爬蟲），因為這樣 Threads 才會在不登入的情況下回傳數字。你可以在 `settings.ini` 用 `user_agent` 更改，但換成別的值之後，Threads 可能就不再回傳數字。
- **這種使用方式可能違反 Meta 的服務條款。** Threads 可能因此限制或封鎖你的網路連線（IP 位址）。是否使用、如何使用，由你自行判斷並承擔責任。
- **它不是 Meta 做的。** ThreadsMonitor 與 Meta Platforms, Inc. 及 Threads 沒有任何關係。
- **它會在你的電腦上保存別人的文字。** 每篇追蹤中貼文的貼文內文會存在它的 `snapshots.csv` 和 `info.txt`，前 200 字也會出現在 `index.csv`。請用對待任何他人內容副本的同樣態度保管這些檔案。
- **瀏覽數是網頁上顯示的數值**，不是官方統計。

到這個專案的 Releases 頁面，下載符合你電腦的檔案：

| 你的電腦 | 要下載的檔案 |
| --- | --- |
| Windows 10 或 11 | `win-x64` |
| Apple 晶片的 Mac（M1、M2、M3、M4 及之後） | `osx-arm64` |
| Intel 晶片的 Mac | `osx-x64` |

**怎麼確認成功：** 程式檔大約 40 MB。

## 第 2 步：解壓縮到專用資料夾

1. 為這個工具建立一個新資料夾，例如在你的使用者資料夾裡建一個 `ThreadsMonitor`。
   - Mac 請**不要**放在「桌面」、「文件」或「下載項目」：macOS 會阻止背景程式寫入這些位置。請改用你的個人專屬資料夾（有房子圖示的那個）。
   - Windows 最好用短一點的路徑，例如 `D:\Threads`（見[同步資料夾](#同步資料夾)）。
2. 解壓縮下載的檔案，把程式移進這個資料夾。

工具產生的所有東西都會出現在同一個資料夾。之後可以搬動整個資料夾，但要先移除排程（第 5 步），搬完再重新設定。

**怎麼確認成功：** 資料夾裡只有一個檔案：`ThreadsMonitor.exe`（Windows）或 `ThreadsMonitor`（Mac、Linux）。

## 第 3 步：在 urls.txt 加入貼文

1. 先執行程式一次（第 4 步會說明怎麼執行）。第一次執行時，它只會建立一份含說明的 `urls.txt`，然後就結束，不會連網。
2. 用「記事本」（Windows）或「文字編輯」（Mac）打開 `urls.txt`。
3. 一行貼一個 Threads 貼文網址。可以從瀏覽器複製網址，或在 Threads App 用「複製連結」。分享連結也可以。
4. 新建立的檔案只有說明文字：每一行都以 `#` 開頭。最後幾行是一個寫成註解的分組範例（`# ## 客戶A`），它不會有任何作用。貼在檔案最後、上方沒有 `## 名稱` 行的網址不屬於任何分組：它們的資料夾會放進名為 `未分組` 的資料夾。要分組時，在那些網址上方寫一行 `## 名稱`（前面不要有 `# `）。
5. 存檔。請維持 UTF-8 編碼（記事本和文字編輯的預設就是）。

**怎麼確認成功：** 下一次執行時，每篇貼文會印出一行，像 `[1/3] @example_user DFakeP0st01 ...`。不是有效貼文網址的行會告訴你是第幾行，並且略過。

### 一行可以寫什麼

```text
# 「#」開頭的行是寫給自己看的註解，會被忽略。
https://www.threads.com/@example_user/post/DFakeP0st01 #video

## Client A
https://www.threads.com/@example_user/post/DFakeP0st02 #video #launch | first post of the campaign
https://www.threads.com/t/CFake_Old01

##Autumn sale
https://www.threads.com/share/ShareFake01/ #sale | shared by the client
```

| 你寫的內容 | 意思 |
| --- | --- |
| 只有網址 | 追蹤這篇貼文。 |
| `## 名稱` 或 `##名稱` | 開始一個分組。它下面的網址，直到下一個分組行為止，都屬於「名稱」這個分組。 |
| 只有 `##`，後面沒有字 | 結束目前的分組。下面的網址又回到沒有分組。 |
| 以 `#` 開頭的行（不是分組行） | 註解，會被忽略。`###` 開頭的行也是註解。 |
| 網址後面的 ` #文字`（`#` 前面有空格） | 一個**標籤**。一行可以有好幾個標籤。 |
| 網址後面的 `\|` | 第一個 `\|` 之後的所有文字是**備註**。 |
| 緊接在網址後面、沒有空格的 `#` | 屬於網址的一部分，不是標籤。 |

用中文或日文輸入法打字也沒關係：

- 全形的 `＃`、`｜` 會當成 `#`、`|`（分組行、標籤、備註都一樣）。
- 從聊天軟體複製時夾帶的看不見的字元（零寬空格、方向控制字元等）會在讀取前移除；emoji 裡面用來組字的看不見字元會保留。
- 標籤寫在網址前面的行，例如 `#video https://www.threads.com/@example_user/post/DFakeP0st01`，整行是註解，所以這篇貼文**不會**被追蹤。程式會提醒：`urls.txt 第 N 行：這一行是註解，所以沒有追蹤；標籤要寫在網址後面：<網址> #標籤 | 備註`。以 `# `（`#` 後面有空格）開頭的行，以及寫成 `#https://...` 刻意註解掉的網址，不會被提醒。
- `urls.txt` 裡發現的問題會寫進 `log.txt`，也會顯示在視窗上（自動排程執行時除外）。

可以接受的網址寫法：`threads.com` 或 `threads.net`、有沒有 `www.`、有沒有 `https://`、`/@帳號/post/代碼`、`/t/代碼`，以及 `/share/代碼` 這種分享連結。分享連結只會還原成貼文網址一次（這一步需要連網），之後就記住。

### 標籤和備註

- 標籤是 1 到 30 個字，不能有空格，也不能有 `;`、`,` 或 `|`。可以用中文，例如 `#影片`。開頭的 `#` 不算在標籤裡。
- 一行最多 20 個標籤。多出來的和無效的標籤會被略過，寫進 `log.txt`，也會顯示在視窗上（自動排程執行時除外）。
- 標籤的比對方式和 `search` 一樣：不分大小寫，全形英數字和半形視為相同，所以 `#Video`、`#video`、`#ｖｉｄｅｏ` 是同一個標籤。顯示時採用檔案裡最先出現的寫法。`--tag` 也用同樣的規則。
- 備註最多 1000 個字。超過的部分會被截掉，`log.txt` 會記下來。
- 網址後面既不是標籤也不是備註的文字會被忽略，並寫進 `log.txt`。
- 標籤和備註**只**存在 `urls.txt` 裡。在這裡改，下次執行時 `index.csv` 和 `info.txt` 就會跟著改（`status` 和 `search` 立刻看得到）。從 `urls.txt` 刪掉某篇貼文那一行，它的標籤和備註也會從 `index.csv` 消失。

### 同一篇貼文寫在好幾行

- 這篇貼文只檢查一次。
- 它的資料夾放在**第一行**所屬的分組。
- 它的標籤是**所有**行的標籤合在一起，備註則用**第一個**不是空白的備註。

## 第 4 步：第一次執行

雙擊程式。會打開一個視窗，檢查 `urls.txt` 裡的每篇貼文，印出摘要表，然後等你按任意鍵。

**怎麼確認成功：** 每篇貼文都會出現一個新資料夾（在它的分組資料夾裡），程式旁邊也會出現 `index.csv`。

第一次打開時，系統可能會跳出警告，因為這個程式沒有付費購買的簽章：

### Windows：SmartScreen

如果看到「Windows 已保護您的電腦」：

1. 點**其他資訊**。
2. 點**仍要執行**。

只需要做一次。

### macOS：Gatekeeper

如果看到「無法打開 ThreadsMonitor，因為 Apple 無法檢查其是否包含惡意軟體」（或「未打開」）：

1. 點**完成**（或**好**）。
2. 打開**系統設定**，進入**隱私權與安全性**。
3. 往下捲，在關於 ThreadsMonitor 的訊息旁邊點**強制打開**，再輸入密碼確認。
4. 再雙擊程式一次。

如果你會用「終端機」，下面這行的效果一樣（請在工具的資料夾裡執行）：

```bash
xattr -d com.apple.quarantine ThreadsMonitor
```

### Linux

先把檔案設成可執行（只要一次），再在工具資料夾的終端機裡執行：

```bash
chmod +x ThreadsMonitor
./ThreadsMonitor
```

## 第 5 步：開啟自動排程

自動排程會在背景每 10 分鐘執行一次程式。它只檢查到期的貼文，所以大部分時候會立刻結束、不會連網。每個資料夾有自己的排程。

**一個資料夾只能讓一台電腦跑排程。** 如果資料夾放在 OneDrive、Dropbox 或 Google 雲端硬碟裡，只能在其中一台電腦開啟排程。如果過去 30 分鐘內有另一台電腦用過這個資料夾，程式會拒絕執行，並告訴你那台電腦的名稱。

### Windows

1. 用檔案總管打開工具的資料夾。
2. 點網址列，輸入 `cmd` 後按 Enter，會在這個資料夾打開黑色的「命令提示字元」視窗。
3. 輸入下面這行並按 Enter：

```bat
ThreadsMonitor.exe install-schedule
```

**怎麼確認成功：** 會印出 `已設定自動排程：Task Scheduler "ThreadsMonitor-..."`。也可以打開**工作排程器**，找到一個名稱是 `ThreadsMonitor-` 加 8 個英數字的工作。

要知道的事：

- 筆電用電池時，排程也會執行。
- 它不會把睡眠中的電腦叫醒。錯過的那一次，會在電腦醒來後盡快補跑。
- 每 10 分鐘會有黑色視窗閃一下，那就是在檢查，是正常的。

### macOS

1. 打開**終端機**（應用程式 → 工具程式）。
2. 輸入 `cd `（後面有一個空格），把工具的資料夾拖進終端機視窗，按 Enter。
3. 輸入下面這行並按 Enter：

```bash
./ThreadsMonitor install-schedule
```

**怎麼確認成功：** 會印出 `已設定自動排程：` 加上 `Library/LaunchAgents` 裡一個 `.plist` 檔的路徑。幾分鐘內，工具資料夾裡的 `log.txt` 就會出現新的紀錄。

### Linux

```bash
./ThreadsMonitor install-schedule
```

程式會先顯示要加入的 crontab 那一行，問過你才會變更。回答 `y` 就會加入。

**怎麼確認成功：** `crontab -l` 會看到一行結尾是 `# ThreadsMonitor-` 加 8 個英數字。

### 關閉自動排程

在同一個資料夾執行同一個指令，把 `install-schedule` 換成 `uninstall-schedule`。

## 第 6 步：看結果

所有 CSV 檔都是含 BOM 的 UTF-8，所以直接雙擊用 Excel 打開，中文和表情符號都正常。時間用你電腦的時區，寫法像 `2026-10-05T14:00:00+08:00`。每個時間另外還有日期欄和小時欄，方便排序和篩選。欄位名稱固定是英文。

只是打開來看永遠沒問題，程式執行中也可以。想修改內容的話，請先看 [Excel](#excel)。

### 執行幾次之後的資料夾

```text
ThreadsMonitor/
  ThreadsMonitor.exe
  urls.txt
  index.csv
  log.txt
  Ungrouped/
    2026-10-06_09h_@example_user_DFakeP0st01/
      snapshots.csv
      info.txt
  Client A/
    2026-10-03_14h_@example_user_DFakeP0st02/
      snapshots.csv
      info.txt
```

- 分組資料夾的名稱來自 `## 名稱` 那一行。沒有分組的貼文放進名為 `未分組` 的資料夾（系統語言不是中文時，這個資料夾叫 `Ungrouped`），兩者之中先建立的那個會一直沿用。
- 貼文資料夾的名稱是 `yyyy-MM-dd_HHh_@帳號_代碼`：你所在時區的發布日期和小時、帳號、貼文代碼。還不知道帳號時，省略 `@帳號_` 這一段。兩個資料夾會同名時，第二個加上 `_2`。
- 建立資料夾時如果還不知道發布時間，資料夾名稱會以 `0000-00-00_` 開頭。知道時間之後程式會把它改名一次，但只限它還直接放在分組資料夾裡的時候。這是程式唯一會改資料夾名稱的情況；它從來不會搬動或刪除資料夾。
- 分組名稱超過 40 個字會被截短。資料夾名稱不能用的字元（`\ / : * ? " < > |`）會換成 `_`，以 `.` 開頭的名稱會把那個點換成 `_`。
- 叫做 `archive` 或 `封存` 的分組會讓裡面的貼文變成唯讀（見[封存](#封存)），所以程式會改放進叫 `_archive` 或 `_封存` 的資料夾。

### index.csv：每篇貼文一行

最新發布的貼文排在最前面。`index.csv` 每次執行都會重建：刪掉它，下次執行就會再出現；你在裡面做的修改也會消失。

| 欄位 | 意思 |
| --- | --- |
| `shortcode`、`username`、`url` | 貼文代碼、帳號和乾淨的網址 |
| `published_date`、`published_hour`、`published_at_local` | 發布時間 |
| `published_at_source` | `page`（從貼文頁面讀到）或 `shortcode`（讀到頁面之前，從貼文代碼推算） |
| `status` | `tracking`（追蹤中）、`done`（72 小時完成）、`gone`（已刪除或改成私人）、`failed`（見[檢查失敗時](#檢查失敗時)） |
| `hours_since_publish` | 最新數字是發文後第幾小時抓到的 |
| `views`、`likes`、`replies`、`reposts`、`quotes`、`shares` | 最新數字 |
| `final_views` … `final_shares` | 72 小時最終數字 |
| `final_captured_at_local` | 最終數字實際抓到的時間 |
| `late_final` | 最終數字是在 72 小時後超過 20 分鐘才抓到（電腦當時沒開），或最後一次檢查一直失敗而改用最後一次成功的數字時為 `true` |
| `added_after_window` | 加入時這篇貼文已經超過 72 小時，只能檢查一次時為 `true` |
| `counts_hidden` | 作者隱藏按讚數和瀏覽數時為 `true` |
| `last_error` | 最近一次的問題，或關於資料夾的訊息（已封存、已從 `urls.txt` 移除、發現副本） |
| `next_due_local` | 下一次自動檢查的時間 |
| `group` | 這篇貼文目前所在的分組資料夾（貼文資料夾直接放在主資料夾時是空白） |
| `folder` | 這篇貼文的資料夾目前在哪裡，例如 `Client A/2026-10-03_14h_@example_user_DFakeP0st02` |
| `archived` | 在封存資料夾裡的貼文為 `true` |
| `tags` | 這篇貼文在 `urls.txt` 的標籤，依字母排序，用 `;` 分隔 |
| `note` | 這篇貼文在 `urls.txt` 的備註 |
| `caption` | 貼文內文的前 200 個字，合併成一行（更長時結尾加 `…`） |

**在 Excel 用標籤篩選：** 對 `tags` 欄使用篩選的「包含」，例如「包含 video」。

### snapshots.csv：一篇貼文的每一次檢查

每個貼文資料夾都有一個 `snapshots.csv`，每次檢查一行。這個檔案才是真正的資料，其他檔案（`index.csv`、`info.txt`）都是從它產生的。

| 欄位 | 意思 |
| --- | --- |
| `captured_at_local`、`captured_date`、`captured_hour` | 這次檢查的時間 |
| `shortcode`、`url`、`username` | 哪一篇貼文 |
| `input_key` | 讓程式認出這篇貼文來自 `urls.txt` 哪一行的短代碼（見下方） |
| `published_at_local`、`published_at_source` | 發布時間，以及這個時間的來源 |
| `counts_hidden` | 作者隱藏按讚數和瀏覽數時為 `true` |
| `hours_since_publish` | 從發布到這次檢查經過幾小時 |
| `status` | `ok`，或檢查失敗的原因：`network_error`、`blocked`、`http_error`、`parse_failed`、`gone`、`exception` |
| `views`、`likes`、`replies`、`reposts`、`quotes`、`shares` | 這次檢查的數字（拿不到時留空） |
| `error` | 出了什麼問題（如果有） |
| `track_hours` | 這篇貼文要追蹤幾小時（72） |
| `caption` | 貼文內文。只寫一次，寫在第一個抓到內文的那一行；之後的行留空 |

關於 `input_key`：程式**不會**保存你貼上的那一行。貼上的網址可能在 `?` 後面帶有追蹤代碼，分享連結也含有私人的分享代碼。程式改存貼文代碼或分享代碼經過單向指紋（SHA-256）後的前 16 個字元。它無法還原成原本的網址，只用來讓程式認出已經還原過的分享連結，不必再連網一次。

### info.txt：給人看的說明卡

每個貼文資料夾還有一個 `info.txt`，寫著網址、帳號、貼文代碼、發布時間、狀態、最新數字、72 小時最終數字、最後錯誤、下次檢查時間、標籤、備註和完整的貼文內文。內容有變化時它會自動重寫，所以不要在裡面寫字。

## 找貼文：status 和 search

這兩個指令只讀你電腦裡的檔案，不會連網，也不會改任何東西，所以隨時都可以執行，排程在跑的時候也可以。先在工具的資料夾打開命令視窗（做法同第 5 步）。Mac 和 Linux 請把 `ThreadsMonitor` 寫成 `./ThreadsMonitor`。

```bat
ThreadsMonitor status
ThreadsMonitor status --tag video
ThreadsMonitor status --tag video --tag launch
ThreadsMonitor status --group "Client A"
ThreadsMonitor search sale
ThreadsMonitor search sale --group "Client A"
ThreadsMonitor search -- -5%
```

- `status` 顯示所有貼文的摘要表。
- `--tag` 只留下有這個標籤的貼文。寫好幾個 `--tag` 時，貼文要**全部**都有才算。標籤不用加 `#`。
- `--group` 只留下這個分組的貼文。它比對貼文目前所在的分組資料夾，或它在 `urls.txt` 那一行的分組，不分大小寫。
- `search` 在帳號、貼文代碼、標籤、備註和完整貼文內文裡找這些字。不分大小寫，全形英數字和半形視為相同，只打一部分也找得到。好幾個字會被當成一整句來找。`search` 也可以加 `--tag` 和 `--group`。
- `--tag` 和 `--group` 只能搭配 `status` 和 `search`。
- 要找以 `-` 開頭的字（例如 `-5%`），在前面加 `--`：`search -- -5%`。`--` 後面的所有字都會被當成要找的字，即使以 `-` 開頭。
- 選項後面沒有接值（例如 `--tag` 寫在最後，或後面緊接另一個選項）會被當成錯誤：程式顯示 `--tag 後面要接一個值（值不能以 -- 開頭）。`，結束代碼是 2。`--group`、`--dir`、`--lang` 也一樣。
- 已封存的貼文和已從 `urls.txt` 移除的貼文也會列出。已從 `urls.txt` 移除的貼文不再有標籤和備註。

摘要表有這些欄：

| 欄 | 意思 |
| --- | --- |
| `#` | 列號 |
| `貼文` | 帳號和貼文代碼 |
| `狀態` | `追蹤中`、`完成`、`已刪除` 或 `失敗`；後面加 `*` 表示已封存 |
| `小時` | 最新數字是發文後第幾小時 |
| `瀏覽`、`讚`、`回覆`、`轉發` | 最新數字 |
| `下次抓取` | 下一次自動檢查的日期時間、`現在`，或沒有時顯示 `-` |
| `符合於` | 只有 `search` 才有：在哪裡找到（`帳號`、`代碼`、`標籤`、`備註`、`內文`） |

**怎麼確認成功：** `status --tag video` 第一行會像 `符合 #video 的貼文：2 篇（共 5 篇）`，`search sale` 第一行會像 `搜尋「sale」：1 篇符合（共 5 篇）`。找不到時會顯示 `沒有符合的貼文。`

## 整理貼文

### 把資料夾搬到別的分組

- `urls.txt` 的分組只在建立貼文資料夾的那一刻使用。要改既有貼文的分組，直接把它的資料夾拖到另一個分組資料夾。之後再改 `## 名稱` 那一行，不會搬動已經存在的資料夾。
- 程式是看 `snapshots.csv` 裡的資料來認貼文，不看資料夾的名稱或位置。你可以改貼文資料夾的名稱、改分組資料夾的名稱，或自己多加幾層子資料夾，最多 6 層。
- 名稱以 `.` 開頭的資料夾會被忽略。

### 封存

在工具資料夾裡任何地方建立一個叫做 `封存` 或 `archive` 的資料夾，把結束的貼文資料夾拖進去。路徑上任何一層叫這兩個名稱都算，不分大小寫。封存資料夾裡的貼文是唯讀的：程式不會再檢查或修改它們，但仍然會列在 `index.csv`，並標記 `archived = true`。把資料夾拖出封存資料夾，程式就會照常處理它。

### 停止追蹤和刪除

- 想**停止追蹤**但保留數字：從 `urls.txt` 刪掉那一行。資料夾和資料都會留著，`last_error` 會寫 `已從 urls.txt 移除，不再追蹤。`。把那一行貼回去就會繼續。
- **刪除貼文資料夾（或把它壓縮成 zip）＝刪除這篇貼文的資料。** 如果網址還在 `urls.txt`，下次執行程式會幫它建一個新的空資料夾。已經超過 72 小時的貼文只會再檢查一次，並標記 `added_after_window`。所以請先從 `urls.txt` 刪掉網址，或把資料夾拖進封存資料夾。
- 如果你複製了貼文資料夾，程式會看到同一篇貼文兩次，在封存以外只剩一份之前，會暫停檢查這篇。`index.csv` 的 `last_error` 欄會告訴你。

## 指令

先在工具的資料夾打開命令視窗（做法同第 5 步）。Mac 和 Linux 請把 `ThreadsMonitor` 寫成 `./ThreadsMonitor`。

| 指令 | 作用 |
| --- | --- |
| （雙擊，不加指令） | 立刻檢查所有追蹤中的貼文、顯示摘要，等你按任意鍵 |
| `update` | 立刻檢查所有追蹤中的貼文（手動更新） |
| `run` | 只檢查到期的貼文（排程用的就是這個） |
| `status` | 只顯示摘要，不連網；可以用 `--tag` 和 `--group` 篩選 |
| `search <關鍵字>` | 用帳號、代碼、標籤、備註或貼文內文找貼文，不連網；關鍵字以 `-` 開頭時用 `search -- <關鍵字>` |
| `install-schedule` | 設定每 10 分鐘自動執行 `run` |
| `uninstall-schedule` | 移除自動排程 |
| `--dir <資料夾>` | 改用另一個工作資料夾，而不是程式所在的資料夾 |
| `--lang en` 或 `--lang zh` | 指定訊息語言 |
| `--help` | 顯示所有指令，以及目前實際生效的檢查頻率（從 `settings.ini` 讀出） |

不認得的指令或選項、或選項後面沒有接值時，程式會顯示說明，結束代碼是 2。

手動更新也會加入快照，但不會改變檢查的時間表。如果同一個資料夾同時啟動兩個程式，第二個會顯示 `這個資料夾已經有另一個 ThreadsMonitor 在執行，這次略過。` 然後結束。

## settings.ini（選用）

只有想改設定時，才需要在工具資料夾建立 `settings.ini`。每一行都是選用的。以 `#` 或 `;` 開頭的行是註解。程式看不懂的行（不認得的設定名稱、不合法的值、沒有 `=` 的行）會被忽略並改用預設值；這一行會寫進 `log.txt`，也會顯示在視窗上（自動排程執行時除外；這類訊息只有英文）。這一行有全形數字（例如 `２４`）時，訊息後面會加上 `(use half-width digits 0-9)`；有全形的 `＝`、`：`、`，` 或 `－` 時，會加上 `(use half-width = : , -)`。請把這些字元改用半形重打。`user_agent` 含有一般 ASCII 以外的字元時會被忽略。

```ini
# 兩次請求之間等幾秒（預設 3）
sleep_seconds = 3
# 一次請求最多等幾秒（預設 30）
timeout_seconds = 30
# 檢查失敗後隔幾分鐘重試（預設 15）
retry_minutes = 15
# 連續失敗幾次就放棄這篇貼文（預設 5）
max_consecutive_failures = 5
# 72 小時後超過幾分鐘才抓到最終數字，就標記 late_final（預設 20）
late_final_tolerance_minutes = 20
# 新貼文要追蹤幾小時（預設 72）；已經開始追蹤的貼文維持原本的設定
track_hours = 72
# 發文後的檢查頻率，格式是「起-迄:分鐘」區段（預設 0 到 72 小時每 60 分鐘）
# 想少檢查幾次（降低被擋的機率），例如前 24 小時每小時、之後每 3 小時：
# poll_bands = 0-24:60,24-72:180
# 設定不合法時會寫進 log.txt，並改用預設值
# 程式向 Threads 自我介紹的身分（預設是 Googlebot，見「風險」）
# user_agent = ...
```

`poll_bands` 的規則：時數是整數、每段的迄大於起、各段依序排列且不重疊、間隔至少 5 分鐘。段與段之間可以留空檔，沒有被區段涵蓋的時間不檢查：

- 發文後經過的時間落在兩段之間的空檔時，下一次檢查是下一個區段的起點。
- 第一個區段的起點大於 0 時，在它之前除了加入時的第一次檢查之外都不檢查。
- 最後一個區段結束後，下一次就直接是追蹤結束時的最後一次檢查。

例如 `poll_bands = 0-24:60,48-72:60`：第 1 到第 24 小時每小時檢查一次、第 48 到第 72 小時每小時檢查一次，第 24 到第 48 小時之間不檢查。

想知道實際生效的是哪個排程，執行 `ThreadsMonitor --help`：最後幾行會依你的 `settings.ini` 說明排程；用上面的例子會顯示 `排程（settings.ini 的 poll_bands）：發文後 0–24 小時每 60 分鐘抓一次，24–48 小時不抓，發文後 48–72 小時每 60 分鐘抓一次，72 小時整再抓最後一次。`

## 檢查失敗時

- **沒有網路**（Wi-Fi 關了、筆電離線）：永遠不算失敗。如果某次執行的第一個檢查就完全連不上，程式這次就先停下來，顯示 `網路無法連線，下次再試。這次不算失敗。`，下次執行再試。貼文絕不會因為你的電腦離線而變成 `failed`。
- **Threads 回應有問題**（拒絕請求、回傳錯誤頁面，或回傳程式看不懂的頁面）：算一次失敗。程式會在 15 分鐘後重試這篇貼文。連續失敗 5 次就放棄。只要成功一次，次數就歸零。
- 如果在 72 小時結束**之前**放棄，狀態是 `failed`，最後一次成功的數字會保留為最終數字。
- 72 小時**之後**，最後一次檢查失敗了仍然會每 15 分鐘重試。連續 5 次都失敗時，貼文會變成 `done`，以最後一次成功的數字當作最終數字，並標記 `late_final = true`。只有在從來沒有成功過任何一次時，才會變成 `failed`。
- **貼文已刪除或改成私人**：貼文立刻變成 `gone`，最後一次成功的數字保留為最終數字。
- **最後一次檢查稍微晚了**：72 小時後 20 分鐘以內抓到的最終數字，仍然算準時。超過 20 分鐘就標記 `late_final = true`。
- **電腦時間錯誤**：時間在未來超過一天的快照會被忽略，`last_error` 會寫 `有時間在未來的快照，請檢查電腦時間。`。如果電腦時間比發布時間還早，那筆快照的小時數寫 0，`error` 欄會寫 `clock_before_publish`。
- **訊息裡絕不會出現密碼**：視窗、`log.txt` 和 `snapshots.csv` 裡的錯誤訊息，會把網址裡的帳號密碼（例如 proxy 位址）換成 `***`，並刪掉 `?` 之後的所有內容。

## 同步資料夾

適用於 OneDrive、Dropbox、Google 雲端硬碟等同步軟體。

- 工具可以放在同步資料夾裡運作，但**只能讓一台電腦**對這個資料夾跑排程。程式會把電腦名稱寫進隱藏的 `.lock` 檔。如果過去 30 分鐘內有另一台電腦用過這個資料夾，程式會停下來並顯示：`這個資料夾正被另一台電腦使用（名稱，最後執行於 時間）。同一個資料夾只能讓一台電腦跑排程，請在其中一台執行 uninstall-schedule。`
- 同步軟體替檔案或貼文資料夾產生衝突副本時（名稱像 `snapshots (1).csv`、`資料夾-電腦名稱` 或 `conflicted copy`），程式會繼續在原本那份追蹤，把每份副本的資料都算進去，並提醒你：`發現同步軟體（OneDrive／Dropbox）產生的衝突副本：…。請手動合併後刪除副本。`
- 使用 OneDrive 的**檔案隨選**（Files On-Demand）時，程式每次執行都會讀取每一個 `snapshots.csv`，包括封存的，這可能讓 OneDrive 把封存資料夾下載回來。如果這會造成困擾，請把封存的貼文放到同步資料夾外面，或把資料夾設成「一律保留在此裝置上」。
- **只有 Windows：** Windows 處理不了太長的路徑（程式採用 240 個字元的上限）。如果資料夾放在 OneDrive 很深的地方，程式會替新貼文改用比較短的資料夾名稱（`yyyy-MM-dd_代碼`）。如果還是太長，這篇貼文不會被檢查，程式會請你把整個工具資料夾搬到比較短的位置，例如 `D:\Threads`。Mac 和 Linux 沒有這個限制。

## Excel

只是看永遠安全。存檔則要注意一點：

- **index.csv**：任何修改都會消失，因為它每次執行都會重建。備註請改寫在 `urls.txt` 的 `|` 後面。
- **snapshots.csv**：最安全的做法是用**另存新檔**存成另一個名稱。如果你已經直接存檔覆蓋，大部分情況程式仍然讀得懂：
  - 欄位是用欄名對應的，所以調換欄位順序沒關係；
  - Excel 用 `;` 或 Tab 分隔欄位存的檔案（某些地區設定常見）也讀得懂，新的行也會用同樣的分隔方式寫入；
  - 新的行會照檔案自己的欄位寫：你刪掉的欄位會略過，你加的欄位會留空；
  - 時間被 Excel 改成讀不懂格式的那一行會被略過（並寫進 `log.txt`）；
  - 如果 `shortcode` 欄完全讀不到，那個資料夾會變成唯讀，`index.csv` 會說明。請用 Excel 另存成 CSV（逗號分隔），或從備份還原。
- 開頭是 `=`、`+`、`-` 或 `@` 這類 Excel 會當成公式執行的文字，程式會在前面加一個 `'`，讓 Excel 把它當成文字顯示。這適用於所有來自程式外部的文字欄位：`index.csv` 的帳號、貼文代碼、分組、資料夾、標籤、備註、貼文內文與 `last_error`；`snapshots.csv` 的帳號、貼文代碼、`error` 與貼文內文。程式讀回 `snapshots.csv` 時會再把 `'` 拿掉。
- 在 Windows 上，檔案正被 Excel 開著時，程式沒辦法寫入：
  - `snapshots.csv`：新的行會先存到同一個資料夾的 `snapshots.pending-...csv`，之後執行時合併回去，資料不會遺失。
  - `index.csv`：這次略過，下次執行時重建。

## 常見問題

**我用 Excel 打開 index.csv 後存檔了，資料會壞嗎？**
不會。`index.csv` 只是總表，每次執行都會重建；真正的資料在每篇貼文的 `snapshots.csv`。不過你對 `index.csv` 做的修改會消失。

**我用 Excel 打開某篇的 snapshots.csv 後存檔了，資料會壞嗎？**
通常不會。程式還讀得懂哪些情況，請看 [Excel](#excel)。如果 `index.csv` 那篇貼文的 `last_error` 出現「無法讀取 snapshots.csv」，請從備份還原，或用 Excel 另存成 CSV（逗號分隔）。

**筆電闔上三天會怎樣？**
闔上的時候不會檢查，錯過的每小時快照事後也補不回來。打開之後，下一次執行會把每篇過期的貼文各檢查一次。期間已經超過 72 小時的貼文，這一次就成為最終數字，寫下實際時間，並標記 `late_final = true`。

**Wi-Fi 斷了一小時，貼文會失敗嗎？**
不會。你這邊的網路問題永遠不算失敗，程式下次執行再試就好。

**我把貼文資料夾搬到別的分組資料夾了。**
沒問題。程式會在新位置找到它、繼續追蹤，`index.csv` 會顯示新的 `group` 和 `folder`。它的標籤和備註仍然來自 `urls.txt`。

**我想改某篇貼文的標籤或備註。**
在 `urls.txt` 改那一行並存檔。`status` 和 `search` 立刻看得到；`index.csv` 和 `info.txt` 下次執行時更新。

**我不小心把網址從 urls.txt 刪掉了。**
它的資料夾和數字都還在。把那一行貼回去，程式會從停下來的地方繼續（錯過的檢查事後補不回來）。

**我想找出內文有「特賣」的所有貼文。**
執行 `ThreadsMonitor search 特賣`。

**我透過 OneDrive 在兩台電腦用同一個資料夾。**
只在其中一台設定排程。另一台仍然可以打開檔案，也可以執行 `status` 或 `search`。

**程式說某篇貼文出現在不只一個資料夾。**
你（或備份工具）複製了它的資料夾。請刪掉多出來的那份，或把它拖進封存資料夾。在那之前不會檢查這篇貼文。

**一週前發的貼文可以追蹤嗎？**
可以，但只會檢查一次，那一次就是它的最終數字，並標記 `added_after_window = true`。

## 疑難排解

| 你看到的訊息 | 怎麼處理 |
| --- | --- |
| `這個資料夾已經有另一個 ThreadsMonitor 在執行，這次略過。` | 等一分鐘再試。 |
| `這個資料夾正被另一台電腦使用…` | 在其中一台電腦執行 `uninstall-schedule`。 |
| `無法寫入鎖定檔…` | `.lock` 檔或資料夾是唯讀的。請取消唯讀設定，或檢查資料夾權限。 |
| `snapshots.csv 正被其他程式（Excel？）開啟…` | 資料沒有遺失：新的快照先存到 `snapshots.pending-...csv`，下次執行會合併回去。請在 Excel 關閉那個檔案。 |
| `index.csv 正被其他程式（Excel？）開啟…` | 在 Excel 關閉它，下次執行會重建。 |
| `urls.txt 第 N 行不是 Threads 貼文網址，已略過` | 檢查那一行：必須是 Threads 貼文網址或分享連結。 |
| `urls.txt 第 N 行：這一行是註解，所以沒有追蹤…` | 這一行以標籤開頭。把標籤移到網址後面：`<網址> #標籤 \| 備註`。 |
| `settings.ini: ignored line ... (use half-width digits 0-9)` 或 `(use half-width = : , -)` | 把那一行的數字和 `=` `:` `,` `-` 改用半形重打。改好之前會用預設值。 |
| `--tag 後面要接一個值…` | 在選項後面直接接值，例如 `--tag video`。要找以 `-` 開頭的字，用 `search -- <關鍵字>`。 |
| `分享連結 … 無法還原` | 改貼貼文本身的網址（`https://www.threads.com/@帳號/post/代碼`），不要用分享連結。 |
| `網路無法連線…` | 你的電腦沒有連上網路。這次不算失敗。 |
| 某篇貼文出現 `blocked` 錯誤 | Threads 暫時拒絕請求。程式每 15 分鐘重試一次（見[檢查失敗時](#檢查失敗時)）。 |
| 某篇貼文顯示 `gone` | 貼文已刪除或改成私人。最後一次的數字會保留為最終數字。 |
| `有時間在未來的快照…` | 檢查電腦的日期、時間和時區。 |
| `發現同步軟體（OneDrive／Dropbox）產生的衝突副本…` | 手動把副本裡多出來的行複製到原本的檔案，再刪掉副本。 |
| `資料夾路徑太長…` | 把整個工具資料夾搬到比較短的位置，例如 `D:\Threads`。 |
| 自動排程好像沒動 | 確認電腦當時有開機、沒有睡眠，再看 `log.txt`。Mac 請確認資料夾不在「桌面」、「文件」或「下載項目」裡。 |

工具資料夾裡的 `log.txt` 會記錄每次執行發生的事。超過 1 MB 時會改名成 `log.1.txt`，再開始寫新的。

需要 .NET 10 SDK。

dotnet test

`build.sh` 會產生 `dist/win-x64`、`dist/osx-arm64`、`dist/osx-x64` 和 `dist/linux-x64`，每個都是一個自帶執行環境的程式。程式本身沒有使用任何第三方套件；測試使用 xUnit。
